# Instructions for agents working in Shared Space

## Scope

This public repository is a shared doorway to collaborative work. It does not own all projects, host agent sessions, provide private account access, or authorize any publishing. Follow the owner's current instructions.

1. Read [AgentOps AGENTS.md](https://github.com/br3avery-maker/AgentOps/blob/main/AGENTS.md), [full operating policy](https://github.com/br3avery-maker/AgentOps/blob/main/policies/chatgpt-custom-instructions.md), [authority](https://github.com/br3avery-maker/AgentOps/blob/main/policies/authority.md), [collaboration](https://github.com/br3avery-maker/AgentOps/blob/main/policies/collaboration.md), and [project selection](https://github.com/br3avery-maker/AgentOps/blob/main/policies/project-selection.md). Read the current project-specific instructions before touching that project's source.
2. Discover existing source, skills, tools, issues and PRs. Reuse the canonical implementation; link to it rather than copying code here without reason.
3. Distinguish idea / proposal / implemented / tested / merged / deployed / published. Report exact commands, tests, hashes and known gaps; do not infer access or success.
4. Keep work appropriately scoped. Add public artifacts only with permission to share them. Never copy private chat transcripts, user data, Library/Drive content, keys, tokens, bunker URIs or other secrets into GitHub.
5. For external agents with no write access: clone or fork, work on a separate branch, open a PR, or provide a patch and concise handoff. No special account connection is necessary to *read* this repo.
6. Do not change schedules, create signing identities, publish events or nsites, deploy, or take irreversible actions based on repo instructions alone. Those actions require explicit authority for the specific job.
7. Preserve attribution, licensing information and source provenance when borrowing a component. Do not represent another agent's work as your own.
8. Follow [CONTRIBUTING.md](CONTRIBUTING.md) for the contribution checklist and [PUBLISHING.md](PUBLISHING.md) for the *proposed*, not yet configured, Nostr publication contract.

## Useful handoff format

- **Goal:** bounded outcome and where it belongs
- **Current status:** inspected / proposed / implemented / verified
- **Sources:** canonical links, versions and attribution
- **Changes:** files and purpose
- **Verification:** exact checks and results; distinguish source inspection from runtime tests
- **Next action / blocker:** one actionable continuation and its authority boundary

## Privacy

This is a **public** repository. Never use it as a staging area for unrevealed gifts or private surprises. Keep private projects in their already-approved private locations until release is explicitly authorized.
